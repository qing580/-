# 六小时分类失败原因与数据采集止损方案

日期：2026-09-06。状态：基于当前实验结果、已保存文档、公开论文页面和开源项目页面的阶段性判断。未新增实验结果，未宣称模型有效。

## 一、核心判断

当前船舶分类效果不佳，不应简单归因于“模型不够复杂”。更可能是三类问题叠加：

1. 数据采集字段不完整：当前桌面采集脚本只订阅 `PositionReport` 和 `ShipStaticData`，未覆盖 `StandardClassBPositionReport`、`ExtendedClassBPositionReport`、`StaticDataReport` 等 AISStream 支持的消息类型。短时间采集中静态船型信息缺失会导致未知船比例高，也会漏掉部分 Class B 船舶行为。
2. 标签可信度不足：当前训练标签来自 AIS 自报船型码，尚未用外部登记资料核验。AIS 自报字段存在缺失、粗粒度和人为错误风险，不能直接当作论文级真值。
3. 当前特征区分力不足：六小时样本中大量船处于低速、停泊或短片段状态，速度、转向、路径长度等粗统计特征更像在描述“当时运动状态”，不稳定地描述船型。货船和油轮在当前特征空间中重叠明显。

因此，继续反复调随机森林、梯度提升或直接上深度学习，短期内很可能是无用功。应先补数据与标签，再做模型。

## 二、与文献和开源项目的对照

公开研究通常不会只用六小时局部 AIS 粗统计直接追求高准确率。常见做法包括：

- 更完整的 AIS 字段：位置、速度、航向、艏向、转向率、导航状态，以及船长、船宽、吃水等静态/几何信息。
- 更严格的轨迹清洗：去除异常跳点、按时间缺口切段、统一采样间隔、控制轨迹长度。
- 更可靠的标签来源：AIS 船型码之外，结合 MarineTraffic 等登记资料或人工核验。
- 更大规模数据和封存测试：多日、多区域或跨区域测试，而不是反复使用同一小测试集。
- 模型从可解释基线开始：Random Forest、LightGBM、XGBoost，再到 CNN/LSTM/TCN/Transformer、轨迹图像与时序融合。

可参考依据：

- AISStream 文档显示 `FilterMessageTypes` 可指定多种消息类型，支持 `PositionReport`、`ShipStaticData`、`StandardClassBPositionReport`、`ExtendedClassBPositionReport`、`StaticDataReport` 等。
- Meyer 与 Kleynhans 的 2025 年 Ocean Engineering 论文使用 AIS 派生特征和 LightGBM，报告 F1 约 0.88-0.90；摘要也指出类别标签选择和预过滤会显著影响表现，货船与油轮存在重叠。
- 2024 年 Electronics 论文《Ship Classification Based on AIS Data and Machine Learning Methods》强调船舶几何特征与轨迹行为特征共同作用，使用长度、宽度、吃水、速度、航向等字段进行分类。
- 2022 年 Ocean & Coastal Management 半监督轨迹分类论文指出，仅使用运动学信息有限，静态信息如长度、宽度、吃水也有价值。
- 开源项目中，轨迹分类/异常检测通常使用规范化轨迹、时间序列模型、质量控制和较大样本，而不是只依赖单日短时样本。

## 三、是不是数据采集不行

结论：当前数据采集“不是完全不能用”，但对论文级船舶分类来说不够。

可以用的部分：

- 已有六小时 AIS 可以做数据审计、规则基线、失败案例分析、Demo 历史回放。
- 对有 `ShipStaticData` 的船，可作为弱标签候选。
- 可以用来设计清洗、切段、特征和核验流程。

不足的部分：

- 消息类型过滤过窄，未覆盖 Class B 相关消息和 StaticDataReport。
- 采集时间仍偏短，静态字段不是每艘船都能在短时间内收到。
- 区域是马六甲/新加坡海峡局部矩形，不能代表整个马六甲海峡。
- 缺少多日封存测试，不能评估泛化。
- 没有外部标签核验，不能证明模型真实准确率。

所以，数据采集需要尽快升级，否则后续模型很可能围着噪声和缺失字段打转。

## 四、建议的止损方案

### 1. 立即升级采集脚本，但不覆盖历史数据

新增一个采集版本，保留旧脚本和旧数据。新版本建议至少订阅：

```text
PositionReport
ShipStaticData
StandardClassBPositionReport
ExtendedClassBPositionReport
StaticDataReport
```

同时在 CSV 中保存 `message_type`、`received_at`、AIS 原始 `Timestamp`、`NavigationalStatus`、`RateOfTurn`、`TrueHeading`、船长/船宽/吃水/目的港等能取到的字段。字段不存在时留空，不伪造。

### 2. 采集策略从“单次六小时”改为“多日分批”

建议先做 3 组独立数据：

- 开发集：1 天或 12 小时，用来调清洗、特征和模型；
- 验证集：另一天同一区域，用来选参数；
- 封存测试集：第三天或不同时间段，只在最终报告时使用。

每次输出目录和文件名包含日期、小时数、bbox、脚本版本。旧结果不覆盖。

### 3. 先核验小批量标签

优先核验已进入 133 艘候选集的船。第一批建议每类 20 艘货船/油轮，再加 20 艘未知或其他编码。核验字段包括 MMSI、IMO、船名、AIS 报文类别、外部登记船型、来源网址、核验日期、冲突备注。

### 4. 模型工作暂时只做训练/验证诊断

在标签和采集升级前，不建议继续追求测试集分数。可以做：

- 特征分布可视化；
- 错误样本剖析；
- 按航行/低速/停泊拆段；
- 控制轨迹长度和采样间隔；
- 对比规则法、Random Forest、LightGBM。

深度学习应等到多日数据和核验标签具备后再作为主实验。

## 五、下一步开发建议

推荐下一步不是继续调模型，而是先做“采集升级 + 标签核验模板增强”：

1. 新建 `采集马六甲AIS数据_增强消息版.py`，支持更多 AISStream 消息类型，并记录脚本版本。
2. 新建或增强核验表模板，把 133 艘候选船按优先级排序，方便人工查证。
3. 保留现有六小时基线为失败基线，不重写结果。
4. 新采集一批数据后，再跑同样审计流程，对比未知比例、静态字段覆盖率、Class B 覆盖情况和候选样本数是否改善。

## 六、不能提前写成成果的内容

- 不能说当前机器学习已经提高分类准确度。
- 不能说未知船都是渔船或小船。
- 不能说 Class B 采集升级一定会提高最终准确率；它只会提高可观测信息覆盖，需要实际验证。
- 不能把开源项目 README 当作本项目实验有效性的证据。
- 不能把 AIS 自报船型码当作独立真值。

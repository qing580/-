# 海上异常监测智能体第一版实施计划

日期：2026-09-20  
状态：实施中；任务0至任务2已完成，任务3首批最小审核库和任务4轻量知识图谱已完成  
依据：`海上异常监测智能体DeepSeek_RAG_知识图谱第一版设计_2026-09-20.md`

## 1. 实施原则

本计划只扩展现有正式统一入口，不重做 AIS 回放、船舶分类、CPA/TCPA 或双端页面。第一轮先打通一个可验证的端到端闭环，再扩大知识库、图谱和评测规模。

实施中始终遵守以下边界：

- 已有 AIS 计算继续作为事实工具，大模型不重算或覆盖其结果。
- DeepSeek API Key 只存在于本地服务进程环境中。
- 未审核资料不进入正式检索。
- 基准测试题不进入知识库索引。
- 不显示碰撞风险数值分，不把内部排序值描述为概率。
- 任何新增准确率、引用正确率或模型收益都必须来自实际评测。

## 2. 技术选型

### 2.1 本地服务

采用 Node.js 内置模块实现本地服务，不引入 Web 框架作为第一版前置依赖。理由如下：

- 当前机器已有可用 Node 24 运行时，现有自动化测试也使用 Node。
- 可以直接复用现有 CommonJS AIS、事件和 CPA/TCPA 逻辑，减少跨语言重写误差。
- Node 自带 HTTP、文件、加密、测试和 `fetch` 能力，足以完成首版 API、静态文件服务与 DeepSeek 请求。
- 桌面图标仍启动同一个项目入口，用户不需要另外打开服务或终端命令。

不在第一版引入 LangChain、LlamaIndex、Neo4j 或向量数据库。后续只有在基准评测证明检索规模或多跳查询确有需要时再引入。

### 2.2 第一版检索

第一版使用可解释的本地混合检索：元数据过滤、短语匹配、关键词/字符片段匹配和确定性排序。每个片段必须携带资料编号、审核状态、机构、版本、地域、页码或章节。

该实现应明确称为“本地审核资料检索”，不能冒充已经完成向量检索。后续可将语义向量检索作为独立实验组加入，并与第一版结果对照。

### 2.3 轻量知识图谱

第一版使用 JSON/JSONL 结构保存实体、关系和来源。自动抽取的关系进入候选区，只有人工审核关系可参与正式回答。图谱查询只支持当前需要的短路径，不提前建设通用图数据库。

## 4. 分步实施任务

## 任务0：冻结基线和清理口径

完成状态：已完成。修改前105项检查通过；正式用户端可见碰撞风险数值分已清理，内部排序值保留。详见`海上异常监测智能体任务0至1实施记录_2026-09-20.md`。

### 操作

1. 备份本次将修改的正式入口文件。
2. 运行现有用户端、管理端、统一入口、回放和可视化测试，记录基线数量和结果。
3. 核对桌面快捷方式实际指向的启动器和正式入口。
4. 清理正式用户端残留的“风险值”“综合分”“X分”等碰撞风险数值表述。
5. 保留内部 `score` 仅用于排序和既有阈值，不作为回答证据或展示字段。

### 验收

- 原有测试全部通过。
- 正式双端页面和本地问答模板不再展示碰撞风险数值分。
- 分类置信度、字段覆盖率等其他百分比不被误删。

## 任务1：建立本地后端和统一启动器

完成状态：已完成。本地Node服务版本0.1.0、健康接口和桌面启动链路已实现；知识库和在线问答仍未实现。详见任务0至1实施记录。

### 操作

1. 新增 Node 本地服务，同时提供静态页面和 `/api/*`。
2. 新增 `/api/health`，返回服务版本、知识库状态和 DeepSeek 是否配置，不返回密钥。
3. 启动器依次查找可用 Node，选择空闲端口，启动本地服务并打开统一入口。
4. 未配置密钥时默认进入“本地证据模式”；需要在线问答时由启动窗口隐藏输入密钥并仅传给子进程。
5. 服务退出时由启动器清理子进程，桌面快捷方式和项目文件位置保持不变。

### 验收

- 双击现有桌面图标仍可启动统一入口。
- 健康检查成功，前端可区分本地模式、在线模式和服务异常。
- 代码、浏览器、URL、日志及截图中不出现 API Key。
- 没有 DeepSeek Key 时，原有回放和本地证据功能仍可使用。

## 任务2：把现有 AIS 能力封装为只读工具

完成状态：已完成。已封装正式演示数据的元数据与上下文接口，复用现有事件、邻船及CPA/TCPA模块，并完成参数、未来数据隔离和窗口上限测试。详见`海上异常监测智能体任务2至3实施记录_2026-09-20.md`。

### 操作

1. 服务端加载正式演示使用的同一份 AIS 数据。
2. 复用现有事件、邻船和 CPA/TCPA 模块；必要的浏览器依赖通过薄适配器隔离，不复制算法。
3. 实现以下工具：当前船舶快照、历史轨迹窗口、邻近船舶、CPA/TCPA、当前事件和数据质量。
4. 工具参数只接受 MMSI、回放时间和有限窗口，禁止任意文件路径。
5. 所有工具输出包含观测时间、单位、数据来源、缺失原因和新鲜度提示。
6. 历史时刻查询禁止读取该时刻之后的观测。

### 验收

- 服务端结果与前端现有同一时刻结果一致。
- AIS 超过5分钟、运动字段缺失或相对速度过小时，CPA/TCPA 正确返回不可用原因。
- 长轨迹空档和平滑显示位置不会进入事实证据。
- 单元测试覆盖有效值、缺失值、陈旧数据、时间边界和未来数据隔离。

## 任务3：建立最小审核知识库和检索器

完成状态：首批最小审核库已完成。已审核并入库IMO AIS指南、MPA STRAITREP网页、项目AIS字段字典和项目采集审计；Singapore Port Information完整出版物、COLREG正式文本和TSIB事故报告仍待获取或审核，不作为检索依据。详见任务2至3实施记录。

### 操作

1. 按现有资料收集说明创建目录和来源登记表。
2. 第一批只处理已人工核验的核心资料：COLREG、AIS 指南、STRAITREP、Singapore Port Information，以及两份官方事故报告。
3. 每份资料保留原件、资料卡和带页码或条款号的提取文本。
4. 编写索引器，只接受资料卡状态为“已审核”的片段。
5. 检索器返回原文片段和引用定位；待核实、已废止或仅背景资料不能作为确定依据。
6. 为“为什么需要关注”“AIS缺失说明什么”“低速是否异常”等问题建立检索回归测试。

### 验收

- 每个检索结果都能回到本地原件和具体页码、章节或条款。
- 未审核资料不会出现在正式检索结果中。
- 检索不到依据时返回明确空结果，不使用模型常识补齐。

## 任务4：建立轻量知识图谱

完成状态：已完成第一版最小可追溯图谱。已实现事件证据链、主题查询、审核来源联动失效和候选关系隔离；当前为本地JSON图谱，不是Neo4j。详见`海上异常监测智能体任务4实施记录_2026-09-21.md`。

### 操作

1. 定义实体、关系、稳定 ID 和来源字段。
2. 先人工建立与第一批资料及基准案例相关的最小关系集。
3. 实现从异常事件回溯观测证据、适用规则和来源的短路径查询。
4. 自动抽取关系只写入候选文件，必须人工审核后才能进入正式图谱。
5. 区分“事件可能涉及规则”和“船舶违反规则”，禁止自动生成违法结论。

### 验收

- 至少支持`事件 -> 证据 -> 规则 -> 来源`的可追溯查询。
- 删除或禁用某条来源后，依赖该来源的路径同步失效。
- 图谱内容不是静态展示数据，能够被问答编排器实际调用。

## 任务5：接入 DeepSeek 官方 API

### 操作

1. 实施前重新核对 DeepSeek 官方 API 文档、模型名称、工具调用格式和当日价格。
2. 客户端设置超时、重试上限、上下文上限、输出上限和每日调用上限。
3. 后端按问题类型调用 AIS 工具、检索器和图谱，再构造最小上下文。
4. 约束输出字段：结论、当前证据、适用依据、局限性、建议关注项和资料来源。
5. 输出守卫检查数值是否来自工具、引用是否来自召回片段、是否出现风险分数或过度法律结论。
6. API 失败时返回本地证据和明确错误状态，不生成伪在线回答。

### 验收

- 网络测试默认关闭，只有显式启用才产生真实调用。
- 相同固定输入可保存模型、参数、检索片段、工具结果、Token、估算费用和耗时。
- 证据不足场景稳定返回拒答和缺失项。
- 任何无法追溯的 AIS 数值或引用都会被拦截或降级。

## 任务6：改造用户端问答

### 操作

1. 保留三个快捷问题并增加自由输入框、发送按钮和停止/重试状态。
2. 提问自动携带当前所选船舶和回放时间，不传输全部 AIS 数据。
3. 回答按已确认六段结构展示，来源可展开查看。
4. 明确区分“在线 DeepSeek + 本地证据”“本地证据模式”和“证据不足”。
5. 回放时间或关注船变化后，旧回答标记为历史上下文，避免误以为已经自动更新。
6. 保留消息中心，不把问答失败误报为航行风险。

### 验收

- 自由输入、快捷问题、加载、超时、取消、重试和离线降级均可操作。
- 回答中的船名、MMSI、时间、DCPA/TCPA 与当前上下文一致。
- 页面在桌面和窄屏下无重叠、溢出或文本截断。

## 任务7：增加管理端智能体审计页

### 操作

1. 增加“智能体审计”导航页，不挤入现有数据与模型页面。
2. 展示单次问答的问题类型、工具调用、检索资料、图谱路径、模型版本、耗时、费用和最终状态。
3. 默认脱敏 MMSI 以外的敏感配置；永不展示 Key、完整环境变量或系统目录。
4. 支持按成功、拒答、降级和失败筛选，并导出脱敏实验记录。

### 验收

- 用户端的一次问答能在管理端找到对应审计编号。
- 审计记录足以复现实验输入，但不包含密钥和无关个人信息。
- 页面清楚区分模型生成内容、工具事实和检索原文。

## 任务8：建立基准集和消融评测

### 操作

1. 从现有马六甲历史回放中选取10至20个第一轮案例，覆盖正常、会遇、行为变化、数据空档和证据不足。
2. 每个案例由人工填写结论边界、必要证据、允许引用和评分标准。
3. 将评测集目录从 RAG 索引目录中物理隔离。
4. 运行四组对照：纯 DeepSeek、DeepSeek + RAG、再加 AIS 工具、再加轻量图谱。
5. 保存每次原始回答、工具结果、检索结果、人工评分和运行参数。

### 验收

- 报告结论正确性、AIS数值一致率、引用正确率、无依据陈述率、合理拒答率、延迟和费用。
- 当前样本规模只支持第一轮可行性判断，不包装成最终泛化结论。
- 如果图谱没有带来可测收益，如实记录，不强行宣称创新。

## 7. 停止条件和负责人决策点

遇到以下情况不继续盲目扩展：

- 第一批资料无法可靠定位条款或页码：先修复资料质量，不扩大知识库。
- AIS工具与前端结果不一致：先完成一致性修复，不接入大模型。
- 在线预检频繁产生无来源数值或法规：加强输出守卫或暂停在线扩样。
- RAG 相比纯模型没有改善引用正确率：检查切分、元数据和检索策略。
- 知识图谱没有改善追溯性或复杂查询：保留最小关系结构，不扩大图数据库投入。
- 费用或延迟超过可接受范围：缩短上下文、缓存结果或评估本地模型，不通过降低证据质量省成本。

## 9. 当前结论

任务0至任务2、任务3首批最小审核库和任务4轻量知识图谱已经完成：本地服务能够返回正式历史回放中的AIS证据、审核资料检索结果，以及`事件 -> 观测证据 -> 已审核知识声明 -> 来源`的可追溯路径。候选关系和失去审核状态的来源不会进入正式路径。当前没有调用DeepSeek、没有产生费用，也没有产生问答效果或新增分类准确率。下一步进入任务5，但在任何付费在线调用前先实现DeepSeek客户端、输出守卫、审计日志和模拟响应测试，再由用户明确确认是否进行少量真实调用。

# 用户端与管理端统一入口设计

日期：2026-09-14

## 1. 背景与目标

项目当前已经分别完成用户端“航行助手”和管理端“海事业务台”演示页面。两端使用同一批六小时增强 AIS 历史数据，但服务对象、导航结构和交互状态不同。

本次目标是增加一个统一产品入口，在一个浏览器页面中通过顶部控件切换用户端和管理端。切换期间保留两端各自的页面状态，并让现有桌面图标始终打开统一入口。

本次工作只整合前端入口，不新增账号系统、真实权限、后端服务、实时监测能力或未经验证的模型结果。

## 2. 已完成基础

- 用户端已有航行首页、附近会遇、航线预评估、环境风险、智能问答与消息五个业务页面。
- 管理端已有综合态势、异常事件中心、事件研判、船舶档案、环境监测、数据与模型六个业务页面。
- 两端均已使用六小时增强 AIS 历史数据和 CPA/TCPA 会遇风险原型。
- 用户端已有 22 项自动化测试记录；管理端已有 24 项自动化测试记录。
- OpenStreetMap 瓦片 403 问题已经通过本地 HTTP 启动方式修复。
- 桌面已有“海上异常监测智能体”快捷方式和项目内图标资源。

以上内容属于既有成果。本设计不把尚未完成的深度学习训练、环境数据接入、在线大模型或真实权限系统描述为已实现。

## 3. 选定方案

采用“统一外壳 + 双端常驻页面”方案。

新增稳定入口：

```text
网页演示/Demo网页/海上异常监测智能体.html
```

统一入口负责产品级顶部栏、视角切换、地址状态和加载错误处理。用户端与管理端仍使用各自现有 HTML、CSS、JavaScript 和嵌入数据，通过两个同源常驻页面容器加载。

两个容器首次打开时均加载，切换只改变可见性，不销毁或重新加载页面。因此，同一次打开期间，用户端的关注船、回放时间和当前功能页，以及管理端的筛选条件、当前事件、船舶档案和处置状态都能够保留。

没有选择以下方案：

- 两个页面互相跳转：实现简单，但切换会重新加载，不能可靠保留状态。
- 完全合并 DOM 和脚本：长期统一程度高，但两端存在重复 DOM 标识和独立状态，当前重构风险过高，容易破坏已有成果。

## 4. 界面设计

顶部统一产品栏保持固定，内容包括：

- 左侧：项目图标和“海上异常监测智能体”名称。
- 中间：`航行助手` 与 `海事业务台` 分段切换控件。
- 右侧：`历史数据演示`、当前视角和数据状态。

主区域只显示当前视角对应的页面。两端原有侧边栏和业务导航继续保留，不增加第三套侧边栏。

视觉风格延续现有青绿色海事系统配色，采用清晰边界、紧凑高度和轻量阴影。按钮使用图标与短标签，不使用夸张营销式布局。顶部栏和页面容器必须在桌面及窄屏视口中保持稳定尺寸，不遮挡地图、时间轴或业务面板。

## 5. 状态与地址规则

- 默认视角为用户端航行助手。
- 用户端地址标记为 `#user`，管理端地址标记为 `#admin`。
- 切换视角时同步更新地址标记，不重新加载内部页面。
- 浏览器刷新后根据地址标记恢复当前视角，但内部业务状态重新初始化。
- 关闭浏览器后重新打开，桌面图标默认进入用户端初始状态。
- 本次不在本地存储中持久化管理端处置状态，避免让演示状态被误认为真实业务记录。

## 6. 数据流与边界

统一入口不复制 AIS 数据，也不重新计算分类或会遇结果。用户端和管理端继续读取各自现有页面中的嵌入数据及脚本逻辑。

数据流为：

```text
桌面快捷方式
  -> 本地 HTTP 启动器
  -> 统一入口
  -> 用户端页面 / 管理端页面
  -> 各端现有数据逻辑与嵌入 AIS 数据
```

统一入口只管理视角，不修改实验数据、船型标签、CPA/TCPA 参数、风险阈值或模型完成度描述。

## 7. 错误处理

- 用户端或管理端加载失败时，仅在对应容器上显示错误说明和“重新加载”命令。
- 一个端加载失败不得阻止另一个端使用。
- 顶部状态只表达页面加载状态和“历史数据演示”属性，不宣称实时在线。
- 地图瓦片错误继续由各端已有提示处理。
- 启动脚本找不到统一入口时，应明确报错，不静默打开旧页面。

## 8. 启动与文件管理

- 修改项目内启动脚本，使其打开统一入口。
- 桌面快捷方式继续指向项目内启动脚本，不复制 HTML、数据或业务代码到桌面。
- 原用户端和管理端文件夹保持不变，仍可独立测试和维护。
- 后续更新任意一端原文件后，统一入口在下次打开时自动加载最新版，无需重建桌面快捷方式。
- 相关代码、图标和说明继续保存在 `马六甲海峡实验` 文件夹中。

## 9. 验证标准

实现完成需满足：

1. 用户端现有 22 项测试全部通过。
2. 管理端现有 24 项测试全部通过。
3. 新增统一入口测试，覆盖默认视角、双向切换、状态保留、地址标记和失败提示。
4. 在真实浏览器中检查两端地图瓦片、船舶标记和主要业务页面。
5. 检查桌面及窄屏视口，顶部栏不得遮挡两端原有控件。
6. 从桌面“海上异常监测智能体”图标启动，必须打开统一入口。
7. 项目资料说明和两端使用说明必须更新，明确统一入口与真实性边界。

## 10. 非本次范围

- 真实用户登录与权限控制。
- 用户端与管理端之间的后端状态同步。
- 新 AIS 数据采集、清洗、标注或模型训练。
- 环境数据接入。
- 在线大模型智能体接入。
- 现有两端业务页面的全面视觉重构。

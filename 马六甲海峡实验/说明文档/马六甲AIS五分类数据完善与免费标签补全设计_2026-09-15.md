# 马六甲 AIS 五分类数据完善与免费标签补全设计

日期：2026-09-15  
状态：设计已确认，尚未实施  
适用项目：国家级大创“基于大模型海上异常检测智能体的构建”

## 1. 目标与边界

本设计服务于基于 1DCNN-LSTM 的船舶轨迹分类研究，并兼顾后续轨迹分析、异常检测、碰撞风险与论文复现。项目采用两阶段路线：

1. 使用现有马六甲海峡增强 AIS 数据完成可信的货船/油轮二分类原型与基线比较。
2. 免费来源优先补充船舶身份和细船型标签，再逐步扩展为渔船、客船、油轮、集装箱船、散货船五分类。

本阶段不重新编写与现有 AISStream 采集器功能重复的实时爬虫。只有当新程序能够提供历史轨迹、细粒度登记标签、可追溯来源或更高轨迹密度时，才允许新增数据下载模块。

所有数据必须限定在马六甲海峡项目区域。当前可比实验区域为北纬 1.0 至 3.5 度、东经 103.0 至 104.5 度；其他地区数据不得混入正式训练和测试。

## 2. 已确认事实与待验证事项

### 2.1 已确认事实

- 截至 2026-09-15，累计增强数据去重后有 57029 行、1500 个 MMSI。
- 严格货船/油轮候选共 435 艘，其中货船 208 艘、油轮 227 艘。
- 按 600 秒切段、50% 重叠生成样本时，16 点窗口有 1116 个，来自 321 艘船；32 点窗口仅 273 个，来自 130 艘船。
- 当前数据可支持货船/油轮 1DCNN-LSTM 原型，不能直接支持五分类。
- 当前五类标签中渔船仅 1 艘、客船 19 艘；AIS 货船编码 70 至 79 不能可靠区分集装箱船与散货船。
- 2026-09-15 独立日期测试的增强特征逻辑回归准确率为 66.07%、宏 F1 为 0.6345，油轮召回率为 40.74%。这些结果不构成深度学习方法已经提高准确率的结论。

### 2.2 待验证事项

- Global Fishing Watch 免费 Vessel API 对现有约 1500 个 MMSI/IMO 的有效匹配率、登记来源覆盖率和细船型覆盖率。
- 免费来源能否可靠补足渔船和客船，并区分集装箱船与散货船。
- 16 点窗口与 32 点窗口在无 MMSI 泄漏条件下的实际泛化差异。
- 原论文 240 维、每项 60 分箱分布特征是否适合当前较短轨迹；若调整分箱数量，必须作为本项目适配实验而非原论文完全复现。
- 免费身份补全后，各类别可用于训练、验证和测试的独立船舶数量。

## 3. 数据来源决策

### 3.1 AISStream

继续使用现有增强采集器获取马六甲实时 AIS。必须保留 PositionReport、ShipStaticData、StandardClassBPositionReport、ExtendedClassBPositionReport、StaticDataReport 及原始 JSON。AISStream 是实时 WebSocket 数据源，不提供历史回放或服务等级保证，因此延长采集只能增加日期和轨迹覆盖，不能单独解决细船型真值问题。

官方文档：https://aisstream.io/documentation

### 3.2 Global Fishing Watch

将 Global Fishing Watch Vessel API 作为第一优先级免费身份补全来源。按照 IMO 优先、MMSI 次之的顺序查询，保留自报信息、登记信息、组合来源、来源年份、匹配依据和原始返回数据。该服务允许非商业研究使用，但结果仍受公共登记覆盖、AIS 自报误差和模型推断不确定性影响。

官方文档：

- https://globalfishingwatch.org/our-apis/documentation/docs/v3/vessels
- https://api-doc.globalfishingwatch.org/our-apis/documentation/docs/v3/general-api-doc/data-caveats

### 3.3 付费历史 AIS

本阶段不购买。免费补全试验完成后，只有在目标类别或连续轨迹仍不足，并且供应商能够提供马六甲区域、所需时间跨度、完整动态字段和可核验细船型时，才进行小额样本验证。不得先购买大批量数据再检查字段。

## 4. 系统架构

系统拆分为五个职责独立的模块。

### 4.1 数据清单器

- 扫描已有 CSV、JSONL 与批次目录。
- 以文件哈希识别重复文件，以批次 ID、时间和坐标范围建立数据清单。
- 检查经纬度是否落在项目区域，生成字段覆盖率与 MMSI/IMO 查询队列。
- 不修改原始文件。

### 4.2 免费身份补全器

- 优先使用 IMO 精确查询，无 IMO 时使用 MMSI。
- 实现请求限速、结果缓存、断点续跑、失败重试和查询日志。
- 每次查询保留原始 JSON，不用解析后的字段替代原始证据。
- 失败、无结果和身份冲突是三种不同状态，禁止统一写成“未知船型”。
- 不抓取违反服务条款或 robots 约束的网站 HTML 页面。

### 4.3 标签裁决器

- 汇总 AIS 自报类别、公共登记类别和来源时间。
- 产生统一的五分类标签、标签等级、裁决原因和人工复核状态。
- 对 MMSI 复用、时间范围不一致、船名/IMO 冲突和多来源矛盾进行隔离，不强制赋值。
- `vessel_type` 及所有外部标签只用于生成监督目标，不得作为轨迹分类模型的输入特征。

### 4.4 1DCNN-LSTM 样本生成器

- 按 MMSI、日期和 600 秒断点切分轨迹，不跨船、跨日期或跨断点生成窗口。
- 第一轮使用 16 点窗口和 50% 重叠；32 点窗口作为对照。
- 序列候选输入为局部相对位移、SOG、COG 的正弦和余弦、加速度、转向变化及 `delta_t`。
- 不把原始 UTC 数值直接当连续运动特征。
- 船长、船宽、吃水作为可选静态分支或消融项，不混入纯轨迹基线。
- 分布特征在完整连续轨迹段上计算；分箱数量变化必须单独记录为适配实验。

### 4.5 防泄漏评估器

- 以独立 MMSI 为划分单位，同一 MMSI 的全部窗口只能属于一个集合。
- 训练集、验证集、测试集的标签来源等级和日期分布必须可追溯。
- 2026-09-15 的 56 艘未见船测试集继续冻结，不参与参数选择。
- 同时报告窗口级和船舶级结果，以船舶级宏 F1 为主指标，并报告准确率、各类别召回率、混淆矩阵和独立船舶数量。
- 比较逻辑回归、1DCNN、LSTM 和 1DCNN-LSTM；不得只报告表现最好的单次划分。

## 5. 数据分层与字段

### 5.1 原始层

必须保留：完整原始 JSON、接收时间、AIS 消息时间、消息类型、批次 ID、区域 ID、边界框、连接与重连记录、解析状态和采集器版本。

### 5.2 轨迹层

必须保留：MMSI、时间、经纬度、SOG、COG、TrueHeading、RateOfTurn、NavigationalStatus、PositionAccuracy、消息类型和数据来源。

可重算衍生字段：`delta_t`、相对位移、距离、加速度、航向变化、COG 正弦和余弦、连续段 ID。衍生字段不得覆盖原字段。

### 5.3 身份标签层

必须保留：MMSI、IMO、船名、呼号、AIS `vessel_type`、船长、船宽、吃水、目的地、外部细船型、来源名称、来源记录时间、匹配字段、原始类别值、统一标签、置信等级、裁决原因和复核状态。

## 6. 标签准入规则

标签分为三级：

- A 级：登记资料与 AIS 身份一致，且来源时间与轨迹时间相容。允许进入正式测试集。
- B 级：IMO 精确匹配，或多个独立来源一致。允许进入训练集和验证集。
- C 级：只有 AIS 自报信息或外部模型推断。只用于探索、预训练或人工复核，不进入正式测试集。

分类规则：

- 油轮：AIS 油轮编码与外部来源一致。
- 集装箱船、散货船：必须存在明确外部细船型依据，不能仅凭 AIS 70 至 79 编码拆分。
- 客船：AIS 客船编码与外部来源一致。
- 渔船：优先使用公共登记资料；仅由外部模型推断的渔船不得进入正式测试集。

## 7. 试验门槛和停止条件

- 先处理已有约 1500 个 MMSI，不立即启动新的长时间实时采集。
- 免费查询前先用小批量验证字段结构、许可、限速、缓存和映射规则。
- 免费身份补全有效率低于 30% 时停止批量查询，先审计标识清洗和匹配逻辑。
- 货船与油轮各有约 150 艘合格独立船时，可以先开展二分类 1DCNN-LSTM 基线；当前是否实际满足仍须按新标签准入规则重新统计。
- 任一五分类类别少于 50 艘合格独立船时，只能做探索分析，不能宣称完成五分类验证。
- 五分类第一阶段工程目标为每类不少于 200 艘独立船。该数字是项目管理门槛，不是文献统一标准，后续应根据学习曲线和置信区间调整。
- 不能用重复窗口或重复轨迹行数替代独立船舶数量。
- 若免费补全后仍缺渔船、客船、集装箱船或散货船，应按缺口定向获取马六甲数据；禁止采集其他区域后无标识混入。

## 8. 错误处理与审计输出

- 网络错误采用有上限的指数退避并记录，不丢弃已有进度。
- 查询结果按请求标识和数据集版本缓存，重复执行默认复用缓存。
- 无结果、请求失败、解析失败、身份冲突、时间冲突分别计数。
- 每轮输出查询覆盖率、A级/B级/C级数量、五类独立船数量、可用连续段和窗口数量、冲突清单、人工复核清单及剩余缺口。
- 所有报告明确区分实际结果与规划目标。

## 9. 验证策略

实施完成后依次验证：

1. 使用少量固定 MMSI 做查询与缓存测试，确认再次执行不会重复请求。
2. 人工抽查 IMO、MMSI、船名、来源年份和细船型的一致性。
3. 构造无结果、接口限流、网络中断和冲突身份样例，验证状态分类与断点续跑。
4. 检查轨迹切段和窗口生成，确保不存在跨 MMSI、跨日期、跨断点样本。
5. 检查训练/验证/测试 MMSI 交集必须为空。
6. 生成免费来源可行性报告，再决定继续实时采集、申请其他免费数据或试购历史 AIS。

## 10. 实施顺序

1. 建立现有数据和 MMSI/IMO 清单。
2. 实现小批量 GFW 身份补全试验与原始响应归档。
3. 确认标签映射和人工复核表。
4. 扩展到全部现有 MMSI，生成五类缺口报告。
5. 先执行货船/油轮二分类数据集与四类模型基线。
6. 根据真实缺口决定是否补采马六甲实时数据或引入历史 AIS。

本设计不预先承诺补全率、五分类准确率或创新性。任何性能结论必须以实施后的独立测试结果为准。

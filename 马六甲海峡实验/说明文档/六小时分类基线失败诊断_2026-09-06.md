# 六小时分类基线失败诊断

日期：2026-09-06。状态：基于现有六小时分类基线结果的只读诊断，未新增模型，未修改 Demo。

## 诊断边界

本记录只分析 `运行结果/六小时分类基线_2026-09-06` 中已有输出和当前脚本。标签仍来自 AIS ShipStaticData 船型码，尚未做外部登记资料核验，因此以下结论只能解释“与报文标签的一致性为何不稳”，不能解释真实船型分类准确率。

## 现有结果复核

候选样本共 133 艘，其中货船 64、油轮 69。按船分层划分后：训练 79 艘（货船 38、油轮 41），验证 27 艘（货船 13、油轮 14），测试 27 艘（货船 13、油轮 14）。三组类别比例接近，划分本身没有明显类别失衡问题。

多数类基线在验证和测试上均为 51.85% 准确率、宏 F1 为 0.3415。随机森林验证准确率 62.96%、宏 F1 0.6250，但测试准确率降至 44.44%、宏 F1 0.4414。梯度提升验证准确率 40.74%、测试准确率 44.44%。因此不能宣称学习模型已超过简单基线。

## 主要观察

1. 货船和油轮在当前特征上高度重叠。货船平均航速均值约 5.105 节、中位数 4.565 节；油轮平均航速均值约 3.692 节、中位数 3.060 节。油轮低速比例均值 0.462，货船为 0.362；但两类四分位范围重叠明显，大量船只处于低速或近停泊状态。

2. 当前特征更像在描述“这 6 小时内是否在移动、移动多久、轨迹是否连续”，而不稳定地描述船型。测试集低速比例均值 0.309、中位数 0.042，低于训练集均值 0.434 和验证集均值 0.458；测试集路径中位数约 8.44 km，高于训练/验证的约 4.92 km 和 4.63 km。这说明同一次随机划分中，不同行为状态分布已经有偏移。

3. 错误样本支持“状态混杂”判断。随机森林测试集中 15 艘错误，既有高速移动的油轮被判成货船，如 414155000、219406000、219772000，也有低速或近停泊的货船被判成油轮，如 304443000、565021000、636018739。梯度提升的错误模式类似。

4. 样本量太小且测试集已曝光。测试集只有 27 艘，错 15 艘即 44.44%，少错 2 艘就会明显改变百分比；当前测试集已经被查看，后续不能继续用它调参或筛模型。

5. 轨迹质量在两类总体上接近，但观测缺口普遍存在。候选货船有效位置点均值约 49.36、最长分段点数均值约 34.08；候选油轮分别约 48.30 和 34.99。两类超过十分钟间隔数均值都在 3.5 次左右。这说明失败不只是某一类别轨迹质量显著更差，而是整体六小时观测在行为片段层面仍偏稀疏。

## 已确认的代码/数据问题

- `源代码/功能特征代码/船舶分类脚本_多类别版.py` 曾将 `40 <= code <= 49 or code == 90` 都归为“高速船”。2026-09-06 已修正为仅将 40-49 码归入“高速船”，90 码会进入“其他”分支。历史输出未因此重跑，引用旧结果时仍需注明版本。
- `源代码/数据采集代码/采集马六甲AIS数据.py` 当前订阅 `FilterMessageTypes: ["PositionReport", "ShipStaticData"]`，未覆盖 Class B 相关动态/静态消息类型。不能由当前数据缺少某类船直接推断海域没有该类船。
- `classification_audit.py` 用 `received_at` 作为时序代理，这是合理的保守处理，但不是精确广播时间。路径、速度变化率、转向率仍会受接收延迟和采样不均影响。

## 暂不应采取的做法

- 不应把模型预测回填为人工核验真值。
- 不应为了提高已曝光测试集分数反复调随机森林或梯度提升参数。
- 不应直接把六小时弱标签基线接入 Demo 作为“更准确分类模型”。
- 不应把当前失败结果解释为“机器学习不可行”；它只说明这组弱标签、小样本、粗特征和同日划分不足以支撑改进结论。

## 建议下一步

推荐下一小阶段目标：建立“可验证分类改进实验”的基础，而不是马上换复杂模型。

1. 已修正旧多类别脚本的 AIS 船型码映射：90 码不再归为高速船。后续若重跑旧分类结果，应使用新输出目录并保留历史结果。
2. 从核验表中优先选取进入训练/验证/测试的 133 艘，按 MMSI/IMO 到可追溯船舶登记网站人工核验船型，记录来源、日期和冲突情况。先做小批量核验即可，例如每类 20 艘。
3. 在不碰已曝光测试集的前提下，用训练/验证集做特征诊断：按运动状态拆分航行/低速/停泊片段，控制点数、观测时长和采样间隔，再比较货船/油轮差异是否增强。
4. 新采集至少一个独立日期的数据，保留为封存测试集；采集脚本是否扩展 Class B 需要先查 AISStream 当前文档和字段结构，再改代码。
5. 如果人工核验和新增日期数据证明标签可靠，再尝试窗口级轨迹模型或轻量时序模型；否则深度学习只会放大标签噪声和数据偏差。

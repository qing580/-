# 海上异常监测智能体任务7：管理端审计页设计（2026-09-21）

## 1. 目标

在现有管理端增加独立“智能体审计”页面，使用户端每次问答产生的审计编号能够被查询、解释和导出，为演示核查与后续论文实验复现提供依据。

本任务只建设审计读取、脱敏展示与导出闭环，不扩大DeepSeek调用，不改变AIS异常判定、CPA/TCPA、知识检索或图谱算法。

## 2. 已确认方案

采用“后端只读审计API + 管理端独立审计页”。不采用浏览器`localStorage`跨端传递，也不依赖手工生成静态报告。

原因：本地JSONL审计日志已经是任务5的事实记录，后端读取可以保留实验可复现性，并能集中执行路径清理、字段白名单和异常行隔离。

## 3. 范围

### 3.1 服务端

新增独立审计读取模块，默认读取审计目录中按日生成的JSONL文件，最多返回最近200条。

新增接口：

- `GET /api/audits`：返回脱敏摘要列表和统计；支持`status`、`mode`、`q`筛选。
- `GET /api/audits/:auditId`：返回单条脱敏审计详情。
- `GET /api/audits/export`：按当前筛选条件导出脱敏JSON实验记录。

接口只允许`GET`，不提供编辑或删除审计记录的能力。

### 3.2 管理端

在“数据与能力”分组增加“智能体审计”导航项，不把内容挤进“数据与模型”页面。

页面包含：

- 统计区：记录总数、成功、守卫拦截/模型错误、本地证据模式。
- 筛选区：审计编号或问题关键词、最终状态、运行模式。
- 列表区：时间、审计编号、问题摘要、MMSI、状态、运行模式。
- 详情区：问题、回放时间、证据ID、来源ID、模型、Token、费用、耗时、最终状态和结构化回答。
- 导出按钮：导出当前筛选结果的脱敏JSON。

桌面采用列表与详情并列布局；窄屏按“统计、筛选、列表、详情”的顺序纵向排列。卡片圆角不超过现有设计规范，状态使用图标和文字，不使用含义不明的数值分。

## 4. 数据规则

### 4.1 摘要字段

- `auditId`
- `createdAt`
- `questionPreview`
- `mode`
- `status`
- `mmsi`
- `replayTime`
- `model`
- `usage`
- `cost`
- `latencyMs`

### 4.2 详情字段

在摘要字段基础上增加：

- 完整问题
- `evidenceIds`
- `sourceIds`
- 守卫或降级原因
- 已通过守卫的结构化回答

本地证据模式没有模型、Token、费用或时延时，界面显示“未发生在线调用”或“不可用”，不显示虚构的零值。

## 5. 安全与脱敏

服务端使用明确字段白名单组装响应，不把原始日志对象直接返回前端。

永不返回：

- API Key、Authorization头及可能的密钥字符串。
- 完整环境变量。
- 审计目录、项目目录、缓存目录等本机绝对路径。
- 内部错误堆栈和原始网络请求头。
- DeepSeek完整原始请求消息。

MMSI、回放时间、证据ID和来源ID属于实验复现必要字段，第一版保留。导出文件同样使用脱敏后的白名单结构。

## 6. 异常处理

- 审计目录不存在：返回空列表和`not_initialized`状态，不报服务器错误。
- 单个JSONL行损坏：跳过该行，返回`skippedInvalidRows`计数，并在管理端提示日志质量问题。
- 审计编号不存在：返回JSON 404。
- 非法筛选值或超长关键词：返回JSON 400。
- 网络或服务不可用：管理端显示审计服务不可用，不把故障显示为航行风险。
- 读取范围始终限制为最近200条，避免日志增长后阻塞界面。

## 7. 数据流

1. 用户端调用`POST /api/ask`。
2. 问答服务写入JSONL并向用户端返回`auditId`。
3. 管理端调用`GET /api/audits`获取脱敏摘要。
4. 管理员选择记录后调用详情接口。
5. 服务端读取原始JSONL、执行字段白名单与敏感信息检查，再返回详情。
6. 导出接口复用同一脱敏器，保证页面与导出边界一致。

- 三个API的成功、400、404和方法限制测试。
- 管理端导航、筛选、详情、空状态、失败状态和导出连接测试。
- 继续运行现有144项完整回归。

### 8.2 浏览器

- 从用户端生成一条本地证据问答，记录审计编号。
- 切换到管理端，通过审计编号定位同一记录。
- 核对MMSI、回放时间、证据ID、来源ID和状态一致。
- 验证“未发生在线调用”显示正确。
- 验证导出内容无密钥、Authorization和本机绝对路径。
- 验证1440×900与390×844无页面级横向溢出、无文本遮挡、无控制台错误。

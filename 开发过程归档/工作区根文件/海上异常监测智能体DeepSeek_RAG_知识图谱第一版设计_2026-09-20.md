# 海上异常监测智能体 DeepSeek + RAG + 知识图谱第一版设计

日期：2026-09-20  
状态：设计已确认，尚未实施  
适用项目：国家级大学生创新创业训练计划“基于大模型海上异常检测智能体的构建”

## 1. 文档目的

本文档固定第一版智能问答系统的范围、数据边界、技术路线和验收标准。它承接现有马六甲海峡 AIS 历史回放、CPA/TCPA、异常事件和双端可视化成果，不重新制作已有功能。

本文记录的是已由负责人确认的设计，不代表 DeepSeek、RAG 或知识图谱已经接入，也不代表其已经提高异常识别或船舶分类准确率。所有效果必须通过后续实验验证。

## 2. 第一版目标

### 2.1 核心目标

第一版以“解释当前历史回放时刻中所选船舶的异常及其证据”为核心：

1. 读取所选船舶、回放时刻、邻近船舶和已有事件结果。
2. 调用现有计算能力获取轨迹窗口、距离、DCPA、TCPA、航速和航向变化等证据。
3. 从人工审核知识库检索适用规则或专业资料。
4. 生成带有证据、来源、局限性和建议关注项的解释。

专业知识问答作为辅助能力，包括海上交通规则、AIS 使用、马六甲海峡报告制度、异常行为概念和事故案例解释。

### 2.2 非目标

第一版不承担以下任务：

- 不替代船长、值班驾驶员、VTS、海事主管机关或司法机构作出航行、执法和责任认定。
- 不让大模型直接读取整批 AIS 文件或全部船舶轨迹。
- 不将平滑回放的视觉估算位置当作真实观测、模型输入或异常证据。
- 不自动抓取网络资料并立即用于正式回答。
- 不把 DeepSeek 自身记忆当作法规原文或事实来源。
- 不预先宣称 RAG、知识图谱或大模型提高了分类准确率或异常检测准确率。
- 不在第一版部署大型图数据库，也不制作缺乏实际查询作用的展示型图谱。

## 3. 已有基础与待开发内容

### 3.1 已有基础

- 马六甲海峡 AIS 历史数据和累计质量审计结果。
- 用户端与管理端统一入口及功能分页面。
- 历史 AIS 平滑回放，并明确区分真实点和显示估算位置。
- 船舶状态、邻船关系、CPA/TCPA 和异常事件展示逻辑。
- 无碰撞风险数值分的分级展示方式。
- 专业资料收集说明、来源入口和人工审核要求。

### 3.2 尚待实现和验证

- DeepSeek 官方 API 后端接入。
- 文档解析、切分、索引、检索和引用链路。
- AIS 工具调用接口及统一证据结构。
- 轻量知识图谱及图谱检索。
- 用户端问答窗口与管理端审计窗口。
- 基准问答集、消融实验和质量评测。
- 调用费用、延迟和失败率统计。

## 4. 总体架构

系统采用“本地数据与计算为主、云端模型负责理解和表达”的架构。

### 4.1 前端层

前端继续使用现有统一入口，并在用户端和管理端加入不同职责的问答视图：

- 用户端：自由输入、快捷问题、当前船舶上下文提示、结构化回答和来源查看。
- 管理端：知识来源、检索片段、工具结果、模型版本、费用、耗时和失败原因审计。

自由输入与快捷问题共用同一问答后端。切换页面或回放时间后，提问时自动读取最新选中状态，不要求用户重复输入 MMSI 和时间。

### 4.2 问答编排层

问答编排层负责：

1. 判断问题类型：当前异常解释、船舶状态、邻船会遇、规则知识或资料检索。
2. 选择所需 AIS 工具和检索范围。
3. 汇总结构化证据并检查新鲜度、缺失值和来源。
4. 生成发送给 DeepSeek 的最小上下文。
5. 对模型输出执行引用、结论边界和格式校验。

大模型不能直接决定 DCPA、TCPA 或事件数值，也不能修改现有检测结果。

### 4.3 AIS 工具层

第一版至少提供以下只读工具：

- 获取当前回放时刻和所选船舶基本状态。
- 获取所选船舶在当前时刻以前的真实轨迹窗口。
- 获取附近船舶及相对距离。
- 获取已有 DCPA/TCPA 计算结果和数据时间。
- 获取当前异常事件、事件类型和组成证据。
- 获取字段缺失、观测陈旧和时间空档提示。

工具结果统一包含 `value`、`unit`、`observed_at`、`source_type`、`confidence_note` 和 `missing_reason` 等信息，避免大模型把缺失值解释为零。

### 4.4 RAG 层

RAG 只使用人工审核通过的本地资料。资料进入正式索引前必须保留：

- 原始文件和来源网址。
- 发布机构、标题、发布日期和获取日期。
- 版本、有效状态、适用区域和语言。
- 审核状态及审核备注。
- 可定位到页码、章节或条款的文本。

检索结果必须返回资料标识、片段、页码或章节、适用性说明。无法定位原文的摘要不能作为法规条款引用。

### 4.5 轻量知识图谱层

第一版使用本地结构化存储或轻量数据库，不以 Neo4j 为前置条件。建议的核心实体为：

- 船舶 `Vessel`
- AIS 观测 `Observation`
- 轨迹窗口 `TrajectoryWindow`
- 会遇关系 `Encounter`
- 异常事件 `AnomalyEvent`
- 证据 `Evidence`
- 规则条款 `Rule`
- 海域 `Region`
- 资料来源 `Source`

建议的核心关系为：

- 船舶产生观测。
- 船舶参与会遇。
- 船舶发生异常事件。
- 事件由证据支持。
- 事件可能涉及规则。
- 规则适用于海域。
- 规则来自资料来源。
- 回答引用证据和资料来源。

图谱主要用于建立可追溯解释路径和受约束的关系查询；法规全文召回仍由 RAG 完成。只有当实体规模、多跳查询和性能测试证明必要时，才评估迁移到 Neo4j。

### 4.6 DeepSeek 模型层

第一版使用 DeepSeek 官方 API。模型职责限于：

- 理解用户意图。
- 根据工具协议选择所需数据。
- 综合已提供证据和检索片段。
- 生成清晰、结构化、带引用的自然语言回答。

模型不负责：

- 编造缺失 AIS 观测。
- 凭常识补写法规条文。
- 将异常事件直接等同于违法或事故责任。
- 将内部排序值描述为风险概率或正式风险分数。

## 5. 标准问答流程

1. 前端提交问题、所选 MMSI、回放时间和当前页面上下文标识。
2. 后端验证参数，拒绝由浏览器提交任意本地文件路径或 API Key。
3. 意图识别器确定需要的 AIS 工具、RAG 检索和图谱关系。
4. AIS 工具读取当前时刻及以前的数据，禁止使用未来观测回答历史时刻问题。
5. RAG 从已审核资料中召回有限数量的相关片段。
6. 图谱组合“船舶—事件—证据—规则—来源”解释路径。
7. 证据门控器判断证据是否足以支持结论。
8. 后端向 DeepSeek 发送最小必要上下文。
9. 输出校验器检查引用、数值来源、结论强度和敏感表述。
10. 前端展示回答；后端保存可复现实验日志。

## 6. 回答规范与拒答策略

### 6.1 当前异常解释

回答固定包含：

1. **结论**：正常、需关注、存在明确会遇风险证据或证据不足。不得输出未经标定的风险分数。
2. **当前证据**：只列工具返回的真实 AIS 指标及其观测时间。
3. **适用规则或专业依据**：列出审核资料的机构、标题和具体定位。
4. **局限性**：指出数据陈旧、字段缺失、轨迹空档、规则适用性或标签不确定性。
5. **建议关注项**：表述为继续观察或核验事项，不生成直接操船指令。
6. **资料来源**：提供可核验引用。

### 6.2 专业知识问答

专业知识回答必须依赖已审核知识库。不同法域、版本或适用范围存在冲突时，必须分别说明，不能自行选定唯一法律结论。

### 6.3 双模式严格策略

- 异常研判证据不足时，必须回答“证据不足，暂时无法判断”，并列出缺少的数据或条件。
- 专业问答检索不到可靠资料时，必须回答“知识库暂无可核验依据”。
- DeepSeek 自身知识只能帮助理解和组织语言，不能替代检索证据。

## 7. 数据与安全边界

### 7.1 允许发送给 DeepSeek 的内容

- 用户当前问题。
- 当前所选船舶的必要标识。
- 当前 AIS 观测和有限轨迹摘要。
- 必要的邻船、DCPA/TCPA 和事件证据。
- 少量已经审核且被检索命中的资料片段。

### 7.2 禁止发送的内容

- 整批 AIS CSV/JSONL 文件或全部历史轨迹。
- 与当前问题无关的船舶数据。
- DeepSeek、AISStream、GFW 或其他服务的 API Key。
- 用户本地目录、系统配置和无关运行日志。
- 未经审核的法规全文或网络抓取内容。

### 7.3 密钥和日志

- DeepSeek API Key 只保存在本地后端环境变量或受限配置中，不写入前端、仓库、截图和实验报告。
- 日志中只记录密钥是否配置，不记录密钥内容。
- 原始模型请求日志应对敏感字段进行脱敏，并设置可清理的保留周期。
- API 失败、超时或额度不足时回退到本地证据展示，不伪造模型回答。

## 8. 费用与运行控制

第一版必须具备以下控制：

- 单次检索片段数和总上下文长度限制。
- 单次最大输出长度和请求超时。
- 每日调用次数或费用上限。
- 会话级缓存和相同问题的结果复用。
- 调用量、输入输出 Token、估算费用、延迟和错误码记录。
- 管理端可查看额度状态并停止外部调用。

具体价格必须以实施时 DeepSeek 官方价格页为准，设计文档不写死价格。

## 9. 知识库准入和更新

第一版采用人工审核后入库：

1. 收集资料并保留原始文件。
2. 创建资料卡，登记机构、版本、适用范围和来源。
3. 检查文件完整性、发布日期和是否被替代。
4. 标记为待审核、已审核、已废止、仅背景参考或存在争议。
5. 只有“已审核”资料进入正式 RAG 索引。
6. 更新资料时保留旧版本和变更记录，不静默覆盖。

详细来源和收集方法见`海上异常监测智能体知识库资料收集说明_2026-09-20.md`。

## 10. 基准评测与论文实验

### 10.1 基准案例

从项目已有马六甲海峡历史数据中选取：

- 正常航行案例。
- 近距离会遇案例。
- 低速、停留或徘徊候选案例。
- 明显航速或航向变化案例。
- 数据缺失、轨迹空档和证据不足案例。

每个案例保存原始 AIS 片段、回放时刻、工具计算结果、人工结论、依据来源、允许的回答边界和审核人。没有可靠人工标签的案例只能标记为待核验，不能进入准确率统计。

### 10.2 对照组

至少比较：

1. 纯 DeepSeek。
2. DeepSeek + RAG。
3. DeepSeek + RAG + AIS 工具。
4. DeepSeek + RAG + AIS 工具 + 轻量知识图谱。

如果样本量有限，先报告案例级结果和置信区间，不夸大总体有效性。

### 10.3 评测指标

- 结论正确性。
- AIS 数值与工具结果一致率。
- 引用正确率和引用可定位率。
- 无依据陈述率。
- 证据不足场景的合理拒答率。
- 人工专业评分及评分者一致性。
- 响应时间、失败率和单问估算费用。

只有当对照实验显示稳定改善后，才能把 RAG 或知识图谱写为已验证贡献。知识图谱若未带来可测收益，应保留为可追溯结构而非宣称提升准确率。

## 11. 开发顺序与阶段门槛

### 阶段一：知识资料入库与引用

- 建立资料目录、资料卡、审核状态和版本记录。
- 完成 PDF/网页文本解析、切分和引用定位。
- 验证检索结果可以回到原文件页码或章节。

门槛：一组代表性问题能够找到正确资料，且所有引用可人工核验。

### 阶段二：AIS 工具接口

- 把现有回放数据、邻船、CPA/TCPA 和事件逻辑包装成只读工具。
- 明确真实观测时间、缺失值和数据新鲜度。
- 清除问答模板中残留的“风险值”等数值分表述。

门槛：工具输出与现有界面、离线计算结果一致，且不会使用未来数据。

### 阶段三：DeepSeek 问答链路

- 接入官方 API、工具调用、费用控制和结构化回答。
- 实现证据门控、拒答和输出校验。
- API 不可用时保留本地证据展示。

门槛：密钥不进入前端和日志；所有数值可追溯；证据不足时能够稳定拒答。

### 阶段四：轻量知识图谱

- 建立核心实体、关系和来源追踪。
- 将图谱查询用于解释路径和关系核验。

门槛：图谱不是静态图片，至少支持从事件回溯证据、规则和来源。

### 阶段五：双端界面

- 用户端完成自由提问、快捷提问、结构化回答和引用查看。
- 管理端完成来源、工具结果、模型、费用和错误审计。

门槛：切换页面和回放时刻后上下文正确，不泄露密钥和本地路径。

### 阶段六：基准评测

- 冻结测试案例和评分规则。
- 完成消融实验并保存原始回答和评分。

门槛：结果可重复，已完成结果与待验证设想在报告中明确分开。

## 12. 第一轮实施建议

第一轮不直接开发完整聊天界面，先完成一个端到端最小闭环：

1. 选取 10 至 20 个代表性历史回放案例。
2. 审核并入库一小组 COLREG、AIS、STRAITREP 和事故报告资料。
3. 实现当前船舶、邻船、CPA/TCPA、事件和资料检索接口。
4. 使用 DeepSeek 官方 API 回答固定问题。
5. 检查证据一致性、引用准确性、拒答行为、耗时和费用。
6. 小规模预检通过后再接入正式前端和扩大知识库。

此顺序可以尽早暴露检索、证据和模型幻觉问题，避免先投入大量界面或图谱开发后才发现核心问答链路不可用。

## 13. 已确认决策清单

- 第一版以当前回放船舶异常解释为主，专业知识问答为辅。
- 支持自由输入和快捷问题，并自动携带当前船舶与时间上下文。
- 使用 DeepSeek 官方 API，并限制发送内容、调用次数和费用。
- 采用双模式严格拒答策略。
- 知识资料必须人工审核后入库。
- 第一版采用轻量知识图谱，是否迁移 Neo4j 由后续需求和测试决定。
- 第一版同时建设论文级基准评测集，不以演示效果代替实验验证。

## 14. 当前结论

该方案能够承接现有 AIS 回放、事件分析和资料收集成果，技术上可分阶段实现。当前仍处于设计完成、实施未开始状态。下一步应先制定阶段一与阶段二的文件级实施计划和验收用例，再开始修改代码。

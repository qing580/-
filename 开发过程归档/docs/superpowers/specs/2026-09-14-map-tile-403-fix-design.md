# 地图瓦片 403 修复设计

日期：2026-09-14

## 问题

用户端航行助手通过 `file://` 直接打开，并使用旧式 `https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png` 地址。OpenStreetMap 公共瓦片服务要求网页请求包含有效 Referer，并要求使用准确的瓦片主机地址，因此当前请求返回 403。AIS 数据、船舶图标和回放逻辑本身没有损坏。

## 目标

- 用户通过一个入口启动本地 HTTP 服务并打开航行助手。
- 页面使用 `https://tile.openstreetmap.org/{z}/{x}/{y}.png`。
- 瓦片失败时显示明确但不遮挡业务界面的状态提示。
- 同步修改页面生成器，重新生成 HTML 后仍保留修复。
- 不引入付费 API、密钥或新的前端框架。

## 实现

1. 修改当前 `用户端航行助手.html` 的 Leaflet 瓦片地址。
2. 修改生成该页面的 Python 模板中的同一地址。
3. 新增 PowerShell 启动脚本：寻找项目已验证的 Python 运行时，在空闲端口启动 `python -m http.server`，再打开 localhost 页面。服务器进程与启动窗口绑定，用户关闭窗口即可停止服务。
4. 为 Leaflet 瓦片层监听 `tileerror` 和 `load`；连续失败时显示“底图服务暂不可用”，加载成功后隐藏提示。提示不影响船舶图标、轨迹和回放控件。
5. 更新项目资料说明，记录必须通过本地 HTTP 入口打开地图。

## 验证

- 静态检查现有 HTML 与生成器不再含 `{s}.tile.openstreetmap.org`。
- 启动 localhost 服务，用真实浏览器打开页面。
- 检查网络返回中不再出现 OSM 403/blocked 瓦片。
- 截图核对底图、船舶图标、关注船面板和底部回放控件均正常显示且不重叠。
- 运行现有用户端功能测试，确认风险计算与交互没有回归。

## 边界

OpenStreetMap 公共瓦片是尽力服务，没有 SLA。本次修复遵守其网页访问要求并解决本地 `file://` 问题，但不承诺公共服务永久可用。论文答辩或正式部署前，应再选择有服务保证的地图供应商或自托管区域底图。
